A Game of Trades: Reading the Steam Market with Hridaya

Shoan Bhatambare · 3 min read · Handwritten

Math sits at the edge of the observable universe and at the heart of modern marketplaces we developed which are still rooted in the barter system of the past. "Give me this, I'll give you that" has evolved into a game on par with the one god plays. Imagine you're at his card table. Do you wonder if he's using math to make you lose?

Moving markets

The Steam Community market[1] is a complex system with millions of moving parts. Even if you would think god moves markets or the moon has an effect on the charts, there's information hidden in them up for grabs still. Hridaya has made it possible to probe into this information with sub second granularity and long term tracking support on the markets movements. The user has been handed the power to observe any item at any time interval.

Hence, not every item needs polling at the same rate. Urgency scores each item by how overdue it is relative to its own interval:

delta = datetime.now() - item['last_update']
urgency = delta.total_seconds() / item['polling-interval-in-seconds']

A ratio above 1 means the item is past due. Sorting by this score lets the poller always chase the most stale item first, instead of cycling through everything on a fixed schedule.

On the other end, requests going out are capped by a sliding window rate limiter[3]:

current_time = time.time()
cutoff_time = current_time - self._window_seconds
self._timestamps = [ts for ts in self._timestamps if ts > cutoff_time]

# Check if we've hit the rate limit
if len(self._timestamps) >= self._max_requests:
    # Calculate exact wait time until oldest timestamp exits the window
    oldest_timestamp = self._timestamps[0]
    wait_time = self._window_seconds - (current_time - oldest_timestamp)
else:
    # We have capacity - grant the token
    self._timestamps.append(time.time())
    return

Timestamps outside the window get dropped first, so the count always reflects requests made in the last window_seconds. If capacity remains, the token is granted immediately; otherwise the wait time is computed exactly from the oldest timestamp still in the window, no polling or guesswork needed.

Reading god's hand

None of this matters without the numbers to point it at. Every scheduled tick writes another row: price, volume, order book depth, timestamped down to the second. One snapshot tells you nothing, a card face down. Months of them, stacked, start to look like a hand being played out in the open. Spikes that repeat on the same weekday. Sell walls that appear right before a price correction. Volume that dries up before it doesn't. If god is running the deck, the tell isn't in any single trade, it's in the pattern across thousands of them, and Hridaya is what's left holding the receipts.
